# Отчёт по проекту KinoLike

Дата отчёта: 19 сентября 2026 года

## 1. Краткое описание

KinoLike — веб-приложение для поиска фильмов и сериалов, ведения личной коллекции, отметки просмотренного, выставления оценок и получения персональных рекомендаций. По назначению проект похож на персональный каталог в стиле Кинопоиска, но дополнен интеграциями с IMDb, AI-сервисами, TorrServer, Jellyfin, VK Video и YouTube.

Рабочая версия интерфейса реализована как одностраничное React-приложение. Серверная часть предоставляет API, работает с PostgreSQL и выступает прокси для внешних сервисов.

## 2. Архитектура и принцип работы

Общий поток данных:

```text
Браузер
  ↓
React + TypeScript + Vite (SPA)
  ↓ /api/*
Express / Node.js
  ├─ PostgreSQL: пользователи, списки, метаданные, кэш
  ├─ TMDB: каталог, поиск, детали, жанры, отзывы и видео
  ├─ IMDb datasets: рейтинги и фильмография
  ├─ OpenAI-compatible API: AI-поиск, анализ и рекомендации
  ├─ Jackett → TorrServer → Jellyfin: поиск и просмотр торрентов
  ├─ VK Video: поиск и потоковое воспроизведение видео
  └─ YouTube/yt-dlp: получение URL трейлеров и потоков
```

Сервер запускается из `server/index.js`. При старте он:

1. Загружает переменные окружения из `.env`.
2. Настраивает Helmet, CORS, rate limit и разбор JSON-запросов.
3. Раздаёт собранный frontend из каталога `client/`.
4. Подключает API-маршруты `/api/*`.
5. Инициализирует PostgreSQL-схему и применяет ещё не выполненные миграции.
6. Запускает планировщик обновления IMDb.
7. Начинает принимать HTTP-запросы на порту `PORT` — по умолчанию `3000`.

Для прямого открытия маршрутов React Router сервер возвращает `client/index.html`, поэтому URL вроде `/movie/550` работает после обновления страницы.

## 3. Frontend

Frontend находится в `src/` и собирается Vite в `client/`. Основные технологии: React 18, TypeScript и React Router.

Основные страницы и сценарии:

- Главная — подборки, популярное кино, тренды, жанры и блок продолжения просмотра.
- Каталог — популярные, трендовые, новые и высокооценённые фильмы/сериалы с фильтрацией по жанрам.
- Поиск — поиск через TMDB с автодополнением.
- Карточка фильма или сериала — описание, рейтинг, IMDb-данные, жанры, режиссёр, актёры, трейлеры, отзывы, AI-сводка и похожие произведения.
- Личные списки — «Хочу посмотреть», «Просмотрено» и «Не интересно».
- Просмотренные — фильтрация, сортировка, оценки, заметки и статистика.
- Рекомендации — персональная подборка, подборка по жанрам, AI-поиск по естественному запросу и discovery-фильтры.
- Страница персоны — фильмография с объединением данных TMDB и IMDb.
- Профиль — изменение профиля и пароля, статистика, экспорт и импорт списка.
- Плеер — отдельная защищённая страница с потоковым воспроизведением, выбором качества и эпизодов.

Авторизация проверяется через `GET /api/auth/me`. JWT хранится в `localStorage` и автоматически добавляется к API-запросам; cookie передаётся с `credentials: include`. Защищённые маршруты перенаправляют неавторизованного пользователя на страницу входа.

Интерфейс поддерживает тёмную и светлую тему, адаптивную навигацию, карточки фильмов, горизонтальные ряды, прогресс просмотра и glassmorphism-стилистику.

## 4. Backend API

В Express подключены следующие группы маршрутов:

| Группа | Назначение |
|---|---|
| `/api/auth` | регистрация, вход, выход, текущий пользователь, профиль и пароль |
| `/api/lists` | добавление, изменение, удаление, экспорт и импорт списков |
| `/api/watched` | просмотренные произведения, оценки и статистика просмотренного |
| `/api/stats` | общая статистика пользователя |
| `/api/tmdb` | поиск, каталог, детали, кредиты, жанры, похожие, видео, отзывы и персоны |
| `/api/recommendations` | генерация, получение, поиск и очистка кэша рекомендаций |
| `/api/streaming` | Jackett, TorrServer и Jellyfin: поиск, добавление, файлы и ссылки |
| `/api/vkvideo` | поиск видео и защищённый прокси потоков VK Video |
| `/api/youtube` | получение URL потока и проксирование YouTube-видео |
| `/api/watch-positions` | сохранение и удаление позиции просмотра |

Большинство пользовательских операций защищено JWT middleware. Для API включён общий rate limit: до 1000 запросов за 15 минут на окно.

## 5. Работа со списками и просмотром

Для каждого пользователя фильм или сериал хранится в `user_lists` с уникальной комбинацией пользователя, TMDB ID и типа медиа.

Текущие статусы:

- `want_to_watch` — хочу посмотреть;
- `watched` — просмотрено;
- `not_interested` — не интересно.

Оценка хранится в диапазоне от 1 до 10. Для просмотренных доступны заметки, дата просмотра, сортировка, фильтры по типу, году и диапазону оценок.

Позиция воспроизведения сохраняется в `watch_positions`. Запись не создаётся для первых пяти секунд, а после прохождения 95% длительности удаляется как завершённая. На главной странице можно продолжить просмотр последних незавершённых видео.

В ранних миграциях существовали статусы `watching` и `on_hold`; миграция `006_remove_collection_statuses.sql` удаляет такие записи и оставляет только актуальные статусы.

## 6. TMDB и хранение метаданных

TMDB — основной источник каталога, изображений и локализованных метаданных. Backend скрывает API-ключ от браузера и кэширует ответы в PostgreSQL в таблице `tmdb_cache`.

Расширенные сведения сохраняются в `media_metadata`, включая:

- название, год, описание и постер;
- жанры;
- режиссёров и создателей;
- актёров и персонажей;
- TMDB ID и тип медиа;
- IMDb ID, рейтинг и число голосов;
- локаль и время обновления.

Для TMDB предусмотрена настройка SOCKS5/VLESS-прокси, что позволяет обходить сетевые ограничения. Кэширование снижает количество повторных запросов и позволяет использовать уже загруженные данные при временной недоступности TMDB.

## 7. IMDb-интеграция

IMDb используется как дополнительный источник, а не как замена TMDB. Основная сущность фильма остаётся привязанной к TMDB, а IMDb добавляет качество и полноту данных.

Реализовано:

- импорт официальных non-commercial datasets IMDb в формате `.tsv.gz`;
- импорт названий, рейтингов, голосов, людей и связей фильмография/персона;
- связывание IMDb-работ с существующими TMDB-сущностями;
- хранение IMDb ID, рейтинга и количества голосов на карточке произведения;
- отдельное быстрое обновление `title.ratings.tsv.gz` без полного импорта;
- планировщик периодического обновления рейтингов;
- фильмография персоны с TMDB- и IMDb-источниками;
- расчёт `work_score` для сортировки релевантных работ.

Команды обновления:

```bash
npm run update-imdb-data
npm run update-imdb-ratings
```

Полный импорт использует staging-таблицы и пакетную обработку. Это позволяет обновлять большие наборы данных без пересканирования всех IMDb-файлов при каждом обновлении рейтингов.

## 8. Рекомендации и AI

В проекте есть два связанных механизма.

### Персональные рекомендации

Сервис `personalRecommendations.js` строит профиль пользователя по просмотренным фильмам и оценкам. Учитываются жанры, ключевые слова, режиссёры, описание, актёры, качество, страны, языки и эпоха выпуска. Дополнительно вычисляется сходство с высоко- и низкооценёнными произведениями.

Оценки пользователя преобразуются в положительные и отрицательные веса: высокая оценка усиливает признак, низкая — ослабляет. Итоговый балл нормализуется в шкалу около 0–100. Результаты дополнительно диверсифицируются: ограничивается число фильмов одного жанра и одного режиссёра.

Рекомендации сохраняются в PostgreSQL и могут генерироваться в фоне после изменения списка или оценки фильма. Для них предусмотрен TTL-кэш.

### AI-поиск и AI-функции

Через OpenAI-compatible API реализованы:

- анализ предпочтений пользователя;
- поиск по естественному запросу, например «мрачный детектив без супергероев»;
- fallback-разбор запроса без LLM при недоступности AI;
- ранжирование кандидатов и генерация объяснения рекомендации;
- подборки по пользовательскому запросу;
- суммаризация отзывов с постоянным кэшем в `ai_review_summaries`.

AI настраивается через `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, лимиты токенов, температуру и TTL кэша. Само приложение не привязано только к OpenAI и поддерживает совместимые API.

## 9. Интеграции просмотра

### Jackett и TorrServer

Пользователь может найти торрент, выбрать результат и передать magnet-ссылку в TorrServer. Backend получает файлы торрента, выбирает поток и формирует URL воспроизведения. Для сериалов предусмотрен выбор файлов и сохранение информации о сезонах.

### Jellyfin

Если настроен Jellyfin, сервер может найти соответствующий элемент в медиатеке, обновить библиотеку и сохранить ссылку на просмотр. Настройки задаются через `JELLYFIN_URL`, `JELLYFIN_PORT` и `JELLYFIN_API_KEY`.

### VK Video

Поиск выполняется по названию, оригинальному названию, году, типу медиа и сезону. Результаты сортируются по совпадению названия и содержат варианты качества. Прямой CDN-URL не отдаётся плееру: запрос проходит через авторизованный backend-прокси.

### YouTube

YouTube используется прежде всего для трейлеров. Backend получает URL потока через `yt-dlp` и отдаёт его frontend-плееру через серверные маршруты.

## 10. База данных

Основные таблицы PostgreSQL:

- `users` — учётные записи и хэши паролей;
- `user_lists` — личные списки, статусы, оценки и заметки;
- `recommendations` — кэш персональных рекомендаций;
- `streaming_links` — сохранённые ссылки TorrServer/Jellyfin;
- `watch_positions` — позиции незавершённого просмотра;
- `tmdb_cache` — кэш ответов TMDB;
- `media_metadata` — постоянные метаданные произведений;
- `genres`, `media_genres`, `media_directors`, `media_actors` — нормализованные связи каталога;
- `ai_review_summaries` — кэш AI-сводок отзывов;
- `people` — данные персон;
- `imdb_titles`, `imdb_ratings`, `person_credits` — локальный IMDb-индекс;
- `imdb_import_runs`, `imdb_dataset_files` и staging-таблицы — служебные данные импорта.

Схема создаётся автоматически. SQL-миграции применяются один раз и отмечаются в таблице `schema_migrations`.

## 11. Запуск

### Docker Compose

```bash
cp .env.example .env
# заполнить TMDB_API_KEY, JWT_SECRET и AI_API_KEY
docker compose up -d --build
```

После запуска приложение доступно на `http://localhost:3001`. Внутри контейнера приложение слушает порт `3000`, а PostgreSQL работает отдельным сервисом.

Основные Docker volume:

- `pg-data` — база данных и аккаунты;
- `image-cache` — кэш изображений;
- `imdb-data` — локальные IMDb-файлы.

Команда `docker compose down -v` удаляет volume PostgreSQL и вместе с ним аккаунты и пользовательские списки.

### Локальная разработка

```bash
npm install
cp .env.example .env
npm run dev
```

Для отдельной разработки frontend используется `npm run client:dev`; Vite проксирует `/api` на backend `localhost:3000`.

## 12. Безопасность и эксплуатация

Реализовано:

- bcrypt-хэширование паролей;
- JWT-аутентификация;
- защищённые пользовательские маршруты;
- Helmet-заголовки;
- CORS с credentials;
- ограничение частоты API-запросов;
- лимит размера JSON-запроса 10 MB;
- серверный прокси для внешних потоков;
- проверка принадлежности пользовательских записей текущему пользователю;
- сохранение ключей и паролей только через переменные окружения.

## 15. Текущее состояние и важные замечания

- TMDB остаётся каноническим источником сущностей и изображений; IMDb — дополнительное обогащение.
- Для работы каталога требуется `TMDB_API_KEY`.
- Для рекомендаций и AI-поиска требуется настроенный OpenAI-compatible API, если не используется fallback-логика.
- Для просмотра через внешние источники нужно отдельно настроить Jackett, TorrServer, Jellyfin и/или VK Video.
- В репозитории присутствуют legacy-файлы в `client/js/`: основной рабочий вход теперь находится в `src/`, но старые файлы и плеер сохраняются для совместимости.
- В рабочем дереве есть изменения и новые файлы, не являющиеся частью этого отчёта; `report.md` добавлен отдельно и не изменяет логику приложения.
